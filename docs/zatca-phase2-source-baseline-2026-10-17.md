# ZATCA Phase 2 — official source baseline (reviewed 17 October 2026)

This record ties every compliance decision in the Seera ZATCA implementation (sprint 1: compliant XML, cryptographic stamp, sandbox clearance and reporting) to the official ZATCA material consulted on 17 October 2026. Third-party articles, forums and libraries were **not** used as authority. When ZATCA publishes a new version of any document below, re-check the decisions table before changing code.

## Developer instructions for the official toolbox (not run here)

1. Register on the Developer Portal (`https://sandbox.zatca.gov.sa/`), download the Compliance and Enablement Toolbox SDK (JDK ≥ 11 and < 15) and its sample files. Do not commit the JAR to this repository; keep it in a developer tools folder.
2. Validate a Seera document: `fatoora -validate -invoice <signed.xml>`; compare `fatoora -generateHash -invoice <unsigned.xml>` with the `invoice_hash` stored on the record (decision D-07); `fatoora -qr -invoice <signed.xml>` to compare the QR (D-11).
3. Obtain a sandbox compliance CSID with the CSR Seera generates (Settings → Generate key pair & CSR → paste the OTP from the Developer Portal), run the compliance checks, then the sandbox production CSID; submit test invoices. Record PASS / WARNINGS / ERRORS in the sprint report.
4. Successful toolbox or sandbox results are development evidence only; production onboarding is an owner step in the FATOORA portal with the company's own OTP.

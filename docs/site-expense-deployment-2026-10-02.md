## Required configuration — reviewed by owner / Finance

1. Category → Accounting expense account: explicitly select an active expense account. Legacy text is not a mapping. Review required receipt, mobile visibility, paid Cash/Bank channel restriction and VAT default. Every Site Expense uses runtime approval regardless of the older Approval Required flag.
2. Cash 1110 / Bank 1120, Input VAT 1300, supplier payable account/control and reimbursement liability 2310 must be appropriate and active. Resolve any collision deliberately with Finance before reimbursement posting.
3. Project cost center: one active `project`-type center linked to the Project where needed. Missing required/ambiguous center leaves the expense approved-awaiting-posting.
4. Site Expenses workflow: active, trigger **Expense Submitted**, **Create Accounting Entry**, sequential required reviewers, correct department/scope, no amount limits. Old sample thresholds are not silently removed. Review all actual required slots and eligible users; requester/submitting editor cannot self-approve.
5. Automatic Posting Rules: Site Expense / Site Expense Approved / **Auto Post ON** if Finance wants immediate ledger posting. OFF or missing active rule means a draft journal for Finance review. Supplier Credit always creates a draft Supplier Bill, regardless of the Site Expense rule; existing bill and journal controls then apply.
6. Permissions: site users Site Expenses view/create; edit for broader corrections; delete only cancels draft. Reviewers view/approve/reject plus runtime eligibility. Finance post/retry and post/process for settlement/reversal. AP and Journal Entries permissions remain separate. No broad permission grants are introduced by migration.
7. Mobile shortcut: user Mobile Access enabled plus Site Expenses view/create. This is responsive online web, not GPS/offline/native functionality.

## Correction / rollback boundary

Do not run `migrate:rollback`: this financial migration is intentionally forward-only. It must not drop expense/receipt history. If failure occurs before the module is used, an owner-reviewed code rollback can retain additive tables; new runtime documents will not be actionable in older code. Once new expenses, approvals, bills or journals exist, prefer a tested forward fix and maintenance rather than a blind old-code switch. Restore a verified DB+private-files backup only through an explicitly approved recovery plan—restoration can discard post-backup transactions.

Posted source documents are immutable. Eligible non-credit, unsettled expense correction uses a reasoned opposite journal in an open VAT period. Supplier Credit uses existing unpaid bill Reopen; its approved source values cannot be independently rewritten. Sealed-period credit notes, source amendment and settled-reimbursement reversal are outside this release.

## 2. Company data readiness (what the seller readiness check requires)

The local development database holds placeholder company data and is not the client's record, so no field can be marked Ready from here. The production Company Profile must be confirmed by the owner; Seera's readiness check (ZATCA Settings → seller readiness, and every record page) evaluates exactly these rules.

| Field | Rule (source) | Status |
| --- | --- | --- |
| Legal name (English) | required (BT-27) | Owner Confirmation Required |
| Legal name (Arabic) | recommended; human-readable invoice must be in Arabic (#4 FAQ) | Owner Confirmation Required |
| VAT registration number | 15 digits, starts and ends with 3 (BR-KSA-39/40) | Owner Confirmation Required |
| Commercial Registration (or other identification) and scheme | one of CRN / MOM / MLS / 700 / SAG / OTH (BR-KSA-08) | Owner Confirmation Required |
| Street, building number (4 digits), district, city, postal code (5 digits), country SA | BR-KSA-09 / 37 / 66 (national address) | Owner Confirmation Required |
| Branch / EGS identity (unit name = certificate CN, serial `1-Seera ERP\|2-<version>\|3-<serial>`, location, industry) | Security Features v1.2 Table 1; entered in ZATCA Settings | Owner Confirmation Required |
| Supported document types (`1100` = standard + simplified) | CSR `title` functionality map | Owner Confirmation Required |
| Company logo for the print view | optional (`logo_path`) | Optional |

No legal or tax value was invented for this gate.

## 3. Company simulation onboarding — not run, and why

The FATOORA simulation environment (`…/e-invoicing/simulation`, `PREZATCA-Code-Signing`) needs the client company's own VAT number in the CSR and a one-hour OTP generated by the owner in the FATOORA simulation portal. Neither was supplied, and the earlier throw-away sandbox identity (dummy VAT `399999999900003`) must not be presented as company verification. Status: **COMPANY SIMULATION VERIFIED — no** for every document type.

When the owner is ready (all inside Seera, no credential ever leaves the encrypted unit row):
1. Set `ZATCA_ENVIRONMENT=simulation` on the test server only (production stays `sandbox` / disabled).
2. ZATCA Settings → create the unit (legal name, VAT, types `1100`, location, industry) → Generate key pair & CSR (template `PREZATCA-Code-Signing` is chosen by the environment).
3. Owner obtains the OTP in the FATOORA simulation portal → Request compliance CSID (OTP used once, never stored) → Run compliance checks (six documents) → Request production CSID (simulation).
4. Approve a standard and a simplified test invoice, create a credit and a debit note against each, Submit each; record the sanitised outcomes (status, rule ids, ICV / PIH continuity) in the evidence document; the expected results are CLEARED for standard documents and REPORTED for simplified ones.

## 4. Production environment controls (verified by `ZatcaProductionControlsTest`)

| Control | State |
| --- | --- |
| Production disabled by default; needs `ZATCA_ENVIRONMENT=production` **and** `ZATCA_PRODUCTION_ENABLED=true` | tested |
| Environment never inferred from `APP_ENV` | tested (APP_ENV=production leaves the ZATCA environment at sandbox) |
| A record signed in one environment is never submitted to another (`environment_mismatch`); the production unit lookup ignores other environments | tested |
| Private key, CSIDs and secrets encrypted with `APP_KEY` (Laravel `Crypt`), never displayed; raw columns are ciphertext | tested |
| Certificate expiry blocks readiness and generation (`unit_certificate_expired`) | added this gate, tested |
| Issuer-specific EGS identity (unit per environment, VAT must match the CSID: `certificate-permissions` on the sandbox) | sandbox evidence |
| Private XML under `storage/app/private/zatca/{env}/{uuid}/`, downloads behind ZATCA Invoicing — export | tested |
| Activity logs, submission rows and screens carry no token, secret or key | tested |

## 5. Production activation steps (documented, not performed)

1. Finance decision on VAT rounding recorded (Option A or B); if B, the implementation sprint is done first.
2. Company simulation verified for all six document types (section 3) and the official SDK run on the exported XML by the owner's Developer Portal account.
3. Owner receives the ZATCA wave notification; production onboarding in the FATOORA portal: a new unit in Seera with `ZATCA_ENVIRONMENT=production` on the production server, CSR, production OTP, compliance CSID, compliance checks, production CSID (`ZATCA-Code-Signing`).
4. `ZATCA_PRODUCTION_ENABLED=true` only after step 3, by the owner, with a dated note in the deployment log; first live documents watched on the register; the 24-hour reporting window for simplified documents monitored.
5. Renewal: the certificate expiry is shown in ZATCA Settings; renew before expiry (Detailed Technical Guidelines v2 §3.2.2).

# Site Expense sprint — 44-point handoff

2 October 2026. This is a release/verification report, not a competing user manual. The authoritative operating instructions remain in `docs/user-guide/`. No production deployment, merge, production database access or next-module development is authorized by this handoff.

1. **Branch / revisions.** `feature/seera-connected-workspaces-2026-09-23`; clean starting HEAD `f0a44be`. The final release HEAD is the documentation/build commit containing this report; its exact hash is supplied in the delivery message and can be checked with `git log -1 --oneline` after pulling. Remote was fetched again after the green suite and matched the starting HEAD before publication.
2. **Source audit.** Reused DocumentNumberService, ApprovalRuntimeService adapters, PostingService, existing Supplier Bill approval, SaveAction, permission/scoping services, private storage and Project workspace panel kit. Category account text was not an enforceable FK; added explicit mapping. Details: [implementation ledger](site-expense-implementation-2026-10-02.md).
3. **Schema.** `site_expenses`, `site_expense_receipts`, category `chart_of_account_id`, unique supplier bill `site_expense_id`. Expense retains original submitter/employee, scoped Project/Site, decimal net/VAT/total, payment details, timestamps, journal/bill links, settlement/reversal references and safe failure reason. Runtime tables are reused.
4. **Lifecycle.** Draft → pending → approved_pending_posting → posted. Rejected stays rejected during correction; resubmission creates another attempt. Cancelled draft is retained. Eligible posted corrections become reversed; no financial hard deletion.
5. **Mobile/site UX.** Operations → Site Expenses → Add, plus `/admin/site-expenses/mobile/create` gated by Mobile Access and create/view permission. One entry screen, draft/save/close/back/submit, scoped selectors, receipt upload and calculated preview. Verified 390px phone and 1440px desktop: no horizontal overflow, one/two columns, minimum 44px form buttons, no browser JS errors. Responsive online web only.
6. **Receipts.** Private `local` disk, randomized stored paths, original filename/MIME/size/type/uploader/timestamps. JPG/PNG/PDF up to 10 MB. Existing receipts remain attached across rejection and correction.
7. **Payment modes.** Cash, Bank, Employee Reimbursement, Supplier Credit. Category Cash/Bank restriction is enforced server-side; arbitrary GL selection is not exposed to site staff.
8. **Cash.** Debit mapped expense and applicable Input VAT; credit selected active Cash control account. Uses existing Finance catalogue, currently code 1110.
9. **Bank.** Same debit side; credit selected active Bank control account, currently 1120. A bank account cannot be forged into Cash mode or vice versa.
10. **Reimbursement.** Requires submitter linked to Employee. Initial posting credits shared payable 2310, not cash. Explicit Finance settlement debits the original liability and credits Cash/Bank. One full settlement per expense; repeats cannot pay twice.
11. **Supplier Credit.** Final approval generates exactly one draft direct/service Supplier Bill with a unique backlink. No separate Site Expense AP journal. Existing Finance bill approval/posting remains mandatory; expense follows the linked journal's actual posted state.
12. **VAT.** Uses existing category VAT treatment and applicable toggle, server-rounded amounts. Staff-supplied VAT amount/total are ignored; only Site Expenses post permission allows rate override. No claim of receipt ZATCA clearance. Existing Finance VAT-period locking remains authoritative.
13. **Mapping.** Explicit active expense account on category, never guessed from legacy text/name. One active Project cost center is derived; missing required or ambiguous mapping blocks accounting with a Finance-visible message. Site staff does not choose GL/cost center.
14. **Posting timing.** Last required approval commits first, then accounting is attempted. Existing posting rule controls immediate posting versus draft-journal review. A draft journal is never labelled posted.
15. **Failure/retry.** Approval survives accounting failure. Approved-awaiting-posting, safe error and audit remain. Finance post/retry retries under the source lock and reuses existing journal/bill; no duplicate document.
16. **Runtime.** SiteExpenseApprovalSubject added to the existing registry. Only registry and module-specific posting-mode validation changed in the engine. Required sequential steps, self-approval exclusion and fresh eligibility checks are retained. No parallel/amount-threshold support claimed.
17. **My Approvals.** PR and Site Expenses share the queue, with module/date/project filters. Scope and actionable eligibility are evaluated before pagination; links lead to the source approval section.
18. **Rejection/resubmission.** Reason required, no accounting, private receipts and previous decisions retained. Authorized correction does not erase rejected state; explicit resubmit creates a new historical attempt.
19. **Project Phase B.** Added scoped Site Expenses panel, contextual Add and View actions, status counts and permission-gated financial summaries. Phase A remains intact.
20. **Project Cost.** Existing posted expense-account journal-line calculation is unchanged. Cash/Bank/Reimbursement flow through their expense journal; Supplier Credit through its bill journal.
21. **No duplicate cost.** Raw Site Expense totals are not added to ledger cost. Drafts/pending documents are not actual cost. Reimbursement settlement has liability/cash lines only; reversal offsets original expense cost.
22. **Permissions.** Site Expenses view/create/edit/delete/approve/reject/post/process/retry/mobile catalogue added without broad grants. Create-only owners can correct their own drafts/rejections. Delete cancels drafts only. Finance retry needs post+retry; settlement/reversal post+process. AP/Journal access remains independently permissioned.
23. **Scope.** Project/Site list, selectors, direct routes, forged IDs, approval eligibility and Project panel are scoped. Site must belong to selected Project. Warehouse-only scope fails closed for expenses.
24. **File security.** Authenticated scoped controller resolves the expense and its own receipt; unrelated receipt IDs and anonymous/cross-scope access are denied. MIME/extension/size checks; private cache headers, nosniff and sandbox; no public URL or filesystem path in output.
25. **Concurrency.** Source row is the first mutex for approval/accounting/retry/bill generation/settlement; unique expense number and bill source link. Real independent MySQL workers contend while the parent holds the row lock, not merely sequential mocked calls.
26. **Correction.** Posted financial source values and source-generated journals/bills cannot be independently edited/deleted. Eligible unsettled non-credit expense reversal creates an opposite entry with reason under existing VAT-period checks. Linked Supplier Credit follows unpaid-bill Reopen; source amendment, sealed-period credit notes and settled reimbursement reversal are not implemented.
